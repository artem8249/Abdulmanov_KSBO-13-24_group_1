# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект демонстрирует применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и воспроизводимость.

- **Название проекта:** Рекомендации товаров на основе покупок бренда H&M для осеннего сезона
- **Автор:** Абдульманов Артём Арсеньевич
- **Группа:** КСБО-13-24
- **Контакт:** "@gybina13"

- **Краткое описание (2-4 предложения):**  
   >Проект посвящён построению сервиса персональных рекомендаций товаров на основе данных ритейлера H&M (история покупок, признаки товаров и клиентов).
   >Используется двухэтапная архитектура: отбор кандидатов через FAISS по BERT-эмбеддингам описаний товаров и последующее ранжирование моделью LightGBM, с обработкой холодного старта по демографии пользователя.
   >Результат — REST API (FastAPI), который по идентификатору пользователя или его демографическим данным возвращает список рекомендованных товаров.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – полные зависимости проекта (Python-библиотеки).
- `requirements.docker.txt` – зависимости для сборки Docker-образа (без CUDA-пакетов, CPU-версия).
- `Dockerfile` – рецепт сборки контейнера с сервисом.
- `.dockerignore` – исключения для сборки образа.
- `report.md` – отчёт по проекту (архитектура, сервис, наблюдаемость, ограничения).
- `notebooks/` – экспериментальные ноутбуки: EDA и прототипы моделей (`exp01_eda`, `exp02_baseline`, `exp03_Ranking`, `exp04_BERT`, `exp05_BERT`).
- `configs/` – конфигурационные файлы:
  - `config.yaml` – пути, параметры предобработки, настройки API;
  - `training.yaml` – параметры обучения и гиперпараметры LightGBM;
  - `inference.yaml` – параметры выдачи рекомендаций и холодного старта.
- `src/` – основной код проекта:
  - `data/` – загрузка и предобработка данных (`make_dataset.py`);
  - `features/` – построение признаков и BERT-эмбеддингов (`build_features.py`);
  - `models/` – обучение и инференс (`train_model.py`, `predict_model.py`);
  - `service/` – HTTP-сервис (`api.py` — FastAPI-приложение, `cli.py` — точка запуска);
  - `utils/` – вспомогательные модули (`config.py`, `metrics.py`);
  - `train.py` – скрипт полного цикла обучения.
- `data/` – данные: сырые в `data_for_project`, обработанные в `data/`.
- `tests/` – тесты.
- `artifacts/train/` – сохранённые артефакты (модель, FAISS-индекс, эмбеддинги, маппинги, история пользователей).

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.11`.
- Для запуска через Docker — установленный **Docker Desktop**.
- Системная библиотека `libgomp1` (нужна для LightGBM) — в Docker устанавливается автоматически; при локальном запуске на Linux может потребоваться вручную (`apt-get install libgomp1`).

### 3.2. Установка окружения (локально)

```bash
# Перейти в папку проекта
cd project

# Создать и активировать виртуальное окружение
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows:
.venv\Scripts\activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

> Примечание: проект разрабатывался с использованием менеджера пакетов `uv`. Файлы `requirements.txt` (полный набор) и `requirements.docker.txt` (CPU-версия для контейнера) сгенерированы из зафиксированного окружения для воспроизводимости.

## 4. Как запустить проект

### 4.1. Запуск обучения модели

```bash
cd project
source .venv/bin/activate      # при необходимости
python -m src.train
```

Скрипт выполняет полный цикл: предобработку данных, построение признаков и BERT-эмбеддингов, построение FAISS-индекса, подбор и обучение LightGBM, сохранение всех артефактов в `artifacts/train/`.

### 4.2. Запуск сервиса (локально)

```bash
cd project
source .venv/bin/activate      # при необходимости
python -m src.service.cli
```

### 4.3. Запуск сервиса через Docker

```bash
cd project
docker build -t recsys:latest .
docker run -p 8000:8000 recsys:latest
```

**Параметры сервиса:**

- Порт: `8000`.
- Эндпоинты:
  - `GET /health` – проверка работоспособности;
  - `POST /recommend` – получение рекомендаций (основной эндпоинт предсказания).
- Документация Swagger: `http://127.0.0.1:8000/docs`.

**Проверка работоспособности:**

```bash
# health-check
curl http://127.0.0.1:8000/health

# пример запроса рекомендаций
curl -X POST http://127.0.0.1:8000/recommend \
  -H "Content-Type: application/json" \
  -d '{"age": 27, "has_fashion_news": true, "top_k": 10}'
```

Или открыть в браузере `http://127.0.0.1:8000/docs` и выполнить запрос через Swagger UI.

## 8. Ограничения и дальнейшая работа

**Текущие ограничения:**

- Модель работает на CPU; BERT-эмбеддинги и FAISS-поиск ресурсоёмки.
- Артефакты загружаются один раз при старте; без них `/recommend` вернёт ошибку.
- Пайплайн рассчитан на офлайн-обучение на фиксированном срезе данных, онлайн-обновления нет.

**Направления развития:**

- Несколько алгоритмов ранжирования с выбором через конфиг;
- структурированное логирование и метрики (Prometheus), хранение истории запросов;
- расширение набора признаков и регулярная валидация качества (MLflow);
- базовая авторизация и отключение `reload` в продакшен-режиме сервиса.
